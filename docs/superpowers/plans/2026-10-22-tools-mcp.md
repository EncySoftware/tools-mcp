# tools-mcp Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An MCP server, `tools-mcp` (NuGet `EncySoftware.ToolsMcp`), through which a signed-in person's agent does everything tools.encycam.com does. The plan also adds the two backend endpoints it needs.

**Architecture:** The work has two parts.
- **Part A** adds two endpoints to the Spring backend in `C:\spryt\tools-encycam-com`.
- **Part B** is a new C# .NET tool in `C:\spryt\tools-mcp`, built the way `C:\spryt\dmc-mcp` is:
  - a stdio MCP server;
  - browser sign-in through the Keycloak client `tools-encycam`;
  - a typed client over the REST API;
  - tool classes grouped by area, replying in prose.

**Tech Stack:**
- Java 17 / Spring Boot (existing backend, MockMvc tests);
- .NET 8 with `RollForward=Major`, `ModelContextProtocol` 1.4.1, `Microsoft.Extensions.Hosting` 8.0.1;
- xUnit 2.8.1;
- GitHub Actions and NuGet trusted publishing.

**Spec:** `docs/superpowers/specs/2026-10-22-tools-mcp-design.md` (in tools-encycam-com). Read it first.

## Global Constraints

**Package and naming**
- Package: net8.0, `RollForward=Major`, `PackAsTool`.
  - `ToolCommandName=tools-mcp`, `AssemblyName=tools-mcp`, `RootNamespace=ToolsMcp`.
  - `PackageId=EncySoftware.ToolsMcp`, `Version=0.1.0`.
- MCP server name in agents' configs: `ency-tools`.

**Sign-in and settings**
- Keycloak `https://webservices.encycam.com/keycloak/`, realm `licsys`, client `tools-encycam`, scope `openid offline_access`.
- No password grant (Direct Access Grants are off on that client).
- API `https://tools.encycam.com/api`, site `https://tools.encycam.com`.
- Environment overrides:
  - `TOOLS_API`;
  - `TOOLS_CLIENT_ID`;
  - `TOOLS_KEYCLOAK_TOKEN_ENDPOINT`;
  - `TOOLS_TOKEN` (debug/CI only);
  - `TOOLS_AUTH_FILE` (tests).
- Auth file: `%APPDATA%\tools-mcp\auth.json`, 0600 on Unix (folder 0700). It holds only the refresh token and the client id.
- Every value lives in `src/Brand.cs`.

**Replies**
- stdout is the protocol, and logs go to stderr only.
- Every tool returns `Task<string>` prose, and no exception escapes. An error starts with `ERROR:` and carries the fix.
- Not signed in: `ERROR: not signed in - run tools-mcp login`.
- 401 from the API: `ERROR: the sign-in has expired or was refused - run tools-mcp login`.
- The backend reports a refusal as `{"status":400,"message":"…"}` (`ApiErrorHandler`). The `message` is passed through as `ERROR: <message>`.
- A reply that leaves something in a library ends with: `In ENCY: the Tools catalogue extension lists your libraries - open it there.`

**Anti-goals**
- `find_components` pageSize is at most 50.
- `download_kit` refuses `format == "gtc"`.
- No tool returns a whole catalogue.
- `create_library` stops at an existing library of the same name unless `force=true`.
- `delete_library` and `remove_from_library` act only on an explicit request, and their descriptions say so.

**Files**
- Default folder `~/Downloads/ENCY tools`; a `folder` parameter overrides it.
- Never overwrite: a taken name gets ` (2)`, ` (3)` and so on. A partial file is deleted.

**Server limits** (passed through, not duplicated)
- 50 libraries per account, 500 items per library, 500 per build.
- 1–200 ids for `compat-counts` and `accepts-among`; at most 200 rows per search page.

**Other rules**
- `socketShape`: `null` means what released ENCY reads; `list` is for ENCY builds after 1 September 2026. Anything else is an error.
- House style:
  - comments explain why, with dated facts;
  - commit messages are `area: sentence` and end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **A token that runs out mid-session, or two tool calls refreshing at once.** Keycloak rotates refresh tokens, so a second refresh with the same token fails. Expected: one refresh, both calls succeed, and no "sign in again" while the stored refresh token is valid. Test: Task 3 `TwoCallsAtOnceRefreshOnce`.
2. **A wrong or unseen id against an expired sign-in.** The agent passes an id that does not exist or sits in a closed catalogue. Expected: "not found" and "sign in again" read differently, so the agent does the right thing. Tests: Task 8 `AnUnknownIdIsNotFoundNotASignInProblem`, Task 6 `AnExpiredSignInAsksToSignInAgain`.
3. **A Cyrillic or odd library or kit name in a file name.** Spring writes such a name as `filename*=UTF-8''…`, and names hold `Ø`, `/`, `:`. Expected: saved as `Токарка.mKit` and a Windows-safe name, never `%D0%A2…`. Tests: Task 4 `AFileKeepsTheNameTheServerGaveIt`, Task 5 `MakesANameSafeForWindowsAndKeepsItsLetters`.
4. **A library that holds items gone from the catalogue.** Expected: show, remove and rename keep those items. Tests: Task 2 `removesWhatIsNamedAndKeepsTheRestAsStored`, Task 10 `RemoveKeepsWhatWasNotNamed`.
5. **Oversized asks.** A pageSize of 1000, 300 ids to `check_fit`, an empty build. Expected: capped or refused with a clear reason, never a raw HTTP error. Tests: Task 7 `PageSizeIsCappedAtFifty`, Task 8 `CheckFitNeedsTwoToFiftyIds`, Task 9 `TheServersReasonComesThrough`.
